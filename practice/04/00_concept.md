# 4장 구현 — 개념 노트

## 1. 구현(Implementation)이란

"머릿속 풀이를 소스코드로 옮기는" 유형. **알고리즘은 단순한데 코드가 길어지는** 문제들이다.
3장 그리디가 "무엇을 고를지 아이디어 싸움"이었다면, 4장은 **"시키는 대로 정확히 옮기기"** 싸움이다.

크게 두 갈래로 나뉜다.

### 완전 탐색 (브루트 포스)
가능한 경우를 **하나도 빠짐없이 전부** 세어 보는 방법.

> "0시 0분 0초부터 N시 59분 59초까지 중 3이 포함된 시각의 개수는?"
> → 86,400가지를 전부 만들어 보고 3이 있는지 확인하면 끝.

**언제 쓰나:** 경우의 수가 작을 때. 보통 **1,000만(10^7) 이하**면 파이썬에서 안전하다.

### 시뮬레이션
문제에 적힌 **동작을 순서대로 그대로 따라가는** 방법.

> "L이면 왼쪽, R이면 오른쪽으로 한 칸. 단 공간을 벗어나면 무시한다."
> → 명령을 하나씩 읽으며 좌표를 갱신하면 끝.

**핵심은 "빠뜨리지 않는 것".** 아이디어가 아니라 꼼꼼함이 점수를 가른다.

## 2. 이 장의 핵심 도구 — 방향 벡터

구현 문제의 절반은 **격자 위를 돌아다니는 문제**다. 상하좌우 이동을 if문 4개로 쓰면 코드가 금방 지저분해진다.

```python
# 이렇게 쓰지 말고
if direction == 'U':
    x -= 1
elif direction == 'D':
    x += 1
elif ...
```

**두 리스트로 묶는다.**

```python
#      북  동  남  서   (시계방향)
dx = [-1,  0,  1,  0]
dy = [ 0,  1,  0, -1]

for i in range(4):
    nx = x + dx[i]      # nx = next x
    ny = y + dy[i]
```

`dx[0], dy[0]`을 짝지어 읽으면 `(-1, 0)` = 위로 한 칸. 이 두 줄로 4방향(또는 8방향) 이동이 전부 처리된다.

> **관례:** 2차원 격자에서 `x`는 **행(위아래)**, `y`는 **열(좌우)**로 쓴다.
> 수학의 x축·y축과 반대라 헷갈리기 쉬우니 `board[x][y]`로 기억하자.

## 3. 격자 문제의 단짝 — 범위 체크

이동한 칸이 판을 벗어났는지 매번 확인해야 한다.

```python
if 0 <= nx < n and 0 <= ny < m:
    # 판 안에 있음 → 이동
else:
    # 벗어남 → 무시
```

`0 <= nx < n` 은 파이썬에만 있는 편한 문법이다. C나 Java였다면 `nx >= 0 && nx < n`으로 써야 한다.

**이 체크를 빠뜨리는 게 구현 문제 오답 1위다.** 음수 인덱스가 파이썬에선 에러가 아니라 "뒤에서부터"로 해석돼 조용히 틀린 답이 나오기 때문이다.

```python
board = [[1, 2], [3, 4]]
board[-1][0]    # 3  ← 에러가 아님! 판을 벗어났는데 값이 나옴
```

## 4. 회전 — 나머지 연산의 재발견

방향을 바꾸는 문제가 자주 나온다. `dx`, `dy`를 시계방향으로 정렬해 뒀다면:

```python
direction = (direction + 1) % 4     # 시계방향 90도 회전
direction = (direction - 1) % 4     # 반시계방향 90도 회전
```

`% 4`가 3 다음을 0으로 되돌려 준다. 3장에서 쓴 `%`가 여기서도 나온다.

```python
>>> (3 + 1) % 4
0
>>> (0 - 1) % 4
3           # 파이썬은 음수 나머지도 알아서 처리해 준다
```

## 5. 이 장에서 쓰는 파이썬 문법

### 2차원 리스트

```python
board = [[0] * m for _ in range(n)]     # n행 m열
board[1][2] = 5                          # 1번 행, 2번 열

# 입력으로 받기
board = []
for _ in range(n):
    board.append(list(map(int, input().split())))
```

**절대 이렇게 만들지 말 것:** `[[0] * m] * n` — 모든 행이 같은 리스트를 가리킨다.

### 문자열 다루기

```python
s = input()              # "R R R U D D"
plans = s.split()        # ['R', 'R', 'R', 'U', 'D', 'D']

s = "a1"
s[0]        # 'a'
s[1]        # '1'
int(s[1])   # 1

str(15)             # '15'   숫자 → 문자열
'3' in str(15)      # False  문자열 안에 '3'이 있나?
'1' in str(15)      # True
```

`in` 연산자로 "포함 여부"를 한 줄에 확인할 수 있다. 완전 탐색에서 자주 쓴다.

### 문자 ↔ 숫자 (아스키 코드)

```python
ord('a')        # 97     문자 → 코드값
ord('c') - ord('a')   # 2      'a'를 0으로 보는 변환
chr(97)         # 'a'    코드값 → 문자
```

체스판 좌표 `a1`, `b3` 같은 걸 배열 인덱스로 바꿀 때 쓴다.

### 반복문 중첩

```python
for h in range(24):
    for m in range(60):
        for s in range(60):
            ...          # 86,400번 실행
```

완전 탐색은 이런 3중 반복이 흔하다. **몇 번 도는지 먼저 계산해 보고** 1,000만을 넘지 않으면 안심하고 쓰면 된다.

## 6. 구현 문제 푸는 순서

1. **문제를 단계로 쪼개 적는다** (코드 쓰기 전에 한글로)
2. 필요한 변수를 정한다 — 현재 위치? 방향? 방문 여부?
3. 한 단계씩 코드로 옮긴다
4. **예제를 손으로 따라가며** 한 줄씩 대조한다

3번에서 막히는 게 아니라 1번을 건너뛰어서 막히는 경우가 대부분이다.
