# 3장 그리디 — 개념 노트

## 1. 그리디(Greedy)란

**지금 이 순간 가장 좋아 보이는 것을 고른다.** 앞뒤 사정 따지지 않고 매 단계에서
제일 이득인 선택을 하고, 그 선택을 되돌리지 않는다.

거스름돈 문제가 대표적이다. 500/100/50/10원 동전이 무한히 있고 1,260원을 거슬러
줘야 한다면:

| 단계 | 고르는 동전 | 남은 돈 |
|---|---|---|
| 1 | 500원 × 2 | 260원 |
| 2 | 100원 × 2 | 60원 |
| 3 | 50원 × 1 | 10원 |
| 4 | 10원 × 1 | 0원 |

총 6개. **큰 단위부터 최대한 많이** 쓰는 게 매 단계의 "가장 좋아 보이는 선택"이다.

## 2. 그리디의 진짜 관문: 정당성

거스름돈 그리디가 통하는 이유는 **큰 화폐 단위가 항상 작은 단위의 배수**이기 때문이다.
그래서 작은 단위 동전들을 조합해도 큰 단위를 대체할 방법이 없다.

만약 동전이 500/400/100원이라면? 800원을 거슬러 줄 때 그리디는
500 + 100 + 100 + 100 = 4개를 고르지만, 정답은 400 + 400 = 2개다. **그리디가 틀린다.**

> 코테에서 그리디 문제를 만나면 항상 자문한다:
> "매 단계 최선을 고르는 게 전체 최선이 된다는 보장이 있나?"
> 보장이 없으면 그리디가 아니라 DP나 완전탐색 문제다.

## 3. 그리디 문제의 냄새

- "최소 횟수로", "최대값을 만들어라" 같은 최적화 요구
- **정렬**과 거의 항상 붙어 다닌다 (큰 것부터 / 작은 것부터 쓰려면 정렬이 필요하니까)
- 입력 크기가 커서(N이 10만, 100만) 완전탐색이 불가능함

## 4. 이 장에서 쓰는 파이썬 문법

```python
# 한 줄에 공백으로 구분된 정수 여러 개 입력받기
n, m, k = map(int, input().split())

# 한 줄에 공백으로 구분된 정수들을 리스트로 받기
data = list(map(int, input().split()))

# 정렬
data.sort()                 # 오름차순, 원본을 바꾼다
data.sort(reverse=True)     # 내림차순
new = sorted(data)          # 원본은 두고 새 리스트를 반환

# 인덱싱 — 파이썬은 0부터 센다
data[0]     # 첫 번째
data[-1]    # 마지막      (정렬 후엔 가장 큰 값)
data[-2]    # 뒤에서 두 번째

# 나눗셈
7 / 2       # 3.5  (실수 나눗셈)
7 // 2      # 3    (몫, 정수)
7 % 2       # 1    (나머지)

# 자주 쓰는 내장 함수
min(data), max(data), sum(data), len(data)

# 반복
for i in range(5):      # 0, 1, 2, 3, 4
    print(i)

while n > 1:
    n -= 1
```

### 몫과 나머지가 왜 중요한가

그리디에서 "무엇을 몇 번 반복할 수 있는가"를 셀 때 `//`와 `%`가 계속 나온다.

```python
# 사탕 17개를 한 사람에게 5개씩 나눠준다면
17 // 5   # 3  → 3명에게 줄 수 있고
17 % 5    # 2  → 2개가 남는다
```

이 "몇 묶음 + 나머지" 사고가 3장 문제들의 핵심 도구다.
